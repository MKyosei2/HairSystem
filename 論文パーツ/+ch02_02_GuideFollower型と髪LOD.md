# 2.2 Guide/Follower型と髪LOD

実時間の髪シミュレーションでは、すべての髪を同じ精度で物理計算することは計算量の面で困難である。そのため、多数の髪のうち一部を代表として計算し、残りを追従させるguide/follower型の考え方や、視点距離・重要度・髪束単位で解像度を変えるLODの考え方が広く用いられてきた。

guide/follower型では、少数のguide hairを物理計算し、多数のfollower hairはguideの変形に基づいて生成または補間する。この方法により、髪全体の本数に対して物理計算の対象を大幅に減らすことができる。特にゲームやリアルタイムアプリケーションでは、見た目に大きく影響する代表毛だけを詳細に計算し、それ以外を簡略化することが実用上重要である。

WardらのAdaptive Wisp Treeは、髪をwispやclusterとして階層的に管理し、必要に応じて表現の解像度を切り替える手法を示している[7]。このようなmultiresolutionな髪表現では、髪の集合を階層的に扱い、状況に応じて計算量を変化させることができる。これは、髪全体の見た目を維持しながら計算負荷を抑えるための重要な考え方である。

また、NVIDIAのGPU Gemsに掲載されたNalu Demoの髪アニメーションとレンダリングでは、実時間GPU環境において髪のシミュレーションと描画をどのように扱うかが示されている[8]。このような実装では、すべての髪を高精度に計算するのではなく、GPU上で扱いやすい形にデータを整理し、描画品質と計算負荷のバランスを取ることが求められる。

これらの既存研究は、髪全体の計算量を削減するために、strand、guide、follower、wisp、clusterといった単位で処理を制御している。一方で、それらの多くは髪1本の内部にある各segmentを、個別の実行時処理経路を持つ単位として扱うものではない。つまり、計算量削減の主な単位は、髪1本、髪束、guide集合、あるいは表示上の重要度である。

本研究は、guide/follower型やLODを否定するものではない。むしろ、それらを前提とした上で、さらに細かい粒度としてstrand内部のSegment Groupを扱う。本研究では、同じstrand内であっても、根元付近はStatic cacheとして再利用し、中間部はDeferred Correction、先端付近はDynamic solveへ送る、といった処理経路の混在を許可する。

したがって、本研究との差分は、髪全体やcluster単位で計算量を減らすのではなく、strand内部のSegment Group単位でStatic / Dynamic / Deferred / Repair / Fallbackを切り替える点にある。また、単に計算対象を減らすだけでなく、false-static率やStatic/Dynamic境界誤差を計測することで、部分的な再利用が安全であるかを評価する点も異なる。
