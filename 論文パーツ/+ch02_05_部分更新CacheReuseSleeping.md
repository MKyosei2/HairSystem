# 2.5 髪以外の部分更新・Cache Reuse・Sleeping

リアルタイム物理シミュレーションでは、すべての要素を毎フレーム同じ精度で更新することは計算量の面で難しい。そのため、動いていない物体の計算を一時的に停止するsleeping、前フレームの結果を再利用するcache reuse、重要度の高い領域だけを更新するpartial updateやactive setといった考え方が用いられてきた。これらは髪に限らず、剛体、布、流体、パーティクルなど幅広い分野で重要である。

剛体シミュレーションでは、十分に静止している物体をsleep状態にし、外力や衝突が発生するまで更新を省略することが一般的である。これにより、シーン内の物体数が多い場合でも計算量を抑えることができる。一方で、誤ってsleepさせた物体が必要なタイミングで起きない場合、衝突の取り逃しや不自然な挙動が発生する。この問題は、本研究におけるfalse-staticの問題と近い。

流体やパーティクルシミュレーションでも、近傍探索や制約解決をすべての粒子に対して同じ頻度で行うと計算量が大きくなる。MüllerらのParticle-Based Fluid Simulation for Interactive Applicationsは、粒子ベース流体を実時間で扱う代表的な研究であり、多数の粒子を効率的に扱うための考え方を示している[9]。このような粒子ベース手法では、空間構造、近傍探索、局所的な相互作用の処理が重要である。

PBDやXPBDに基づく柔軟物体シミュレーションでも、すべての制約を常に同じ反復数で解くのではなく、計算予算や安定性に応じて処理量を調整する必要がある[5][6]。このような処理量調整は、実時間性を確保するためには不可欠である。

しかし、部分更新やcache reuseには危険もある。動いていないと判断した要素が実際には動くべきだった場合、見た目や物理挙動が破綻する。特に髪のように多数の細いstrandが連続的につながっている構造では、一部だけをStaticにした結果、隣接するDynamic部分との境界が不自然になる可能性がある。この問題は、単に再計算を減らすだけでは解決できない。

本研究では、髪以外の分野で使われてきたsleeping、partial update、cache reuseの考え方を参考にしつつ、それをそのまま髪に適用するのではない。髪strand内部のSegment Groupごとにcertificate、cache validity、runtime stateを持たせ、Static reuseが安全かどうかを判断する。また、誤ってStatic化されたgroupをfalse-staticとして明示的に計測する。

本研究との差分は、部分更新やcache reuseそのものではなく、その危険性をSegment Group単位で評価する点にある。既存のsleepingやcache reuseでは、計算量削減が主目的となることが多い。一方、本研究では、再利用率だけでなくfalse-static率、Static/Dynamic境界誤差、watchdog repair数を同時に評価し、再利用の安全性を測定する。これにより、単なる高速化ではなく、安全なStatic reuseを目指す。
